# OmniBrain – Week 2: LangGraph Supervisor and Query Routing

## Overview

Week 2 of the OmniBrain project focuses on building the **Agentic Architecture** using LangGraph.

The main objectives completed in this module are:

1. Build a LangGraph state machine.
2. Implement a Supervisor node.
3. Route user queries to the appropriate specialized agent.
4. Test routing between Text, SQL, and Vision agents.

The project plan specifies that the Supervisor evaluates a user's query and routes it to the appropriate sub-agent.

## Components

### 1. Supervisor

File:

```text
agents/supervisor.py
```

The Supervisor receives the user's query and determines which specialized agent should handle it.

The current prototype uses keyword-based routing.

Examples:

```text
Document/revenue question → Text Agent
Stock/database question   → SQL Agent
Chart/image question      → Vision Agent
```

## LangGraph Workflow

File:

```text
graph/workflow.py
```

The workflow uses a LangGraph `StateGraph`.

The graph contains:

```text
START
  ↓
Supervisor
  ↓
Conditional Routing
  ↓
Text / SQL / Vision
  ↓
END
```

The Supervisor's routing decision determines the next node in the graph.

---

## State

The graph maintains the following state:

```python
class GraphState(TypedDict, total=False):
    query: str
    next_agent: str
    response: str
```

### State fields

| Field        | Description                              |
| ------------ | ---------------------------------------- |
| `query`      | User's input question                    |
| `next_agent` | Agent selected by the Supervisor         |
| `response`   | Response generated by the selected agent |

## Future Work

The current implementation is a routing prototype. The next integration steps are:

1. Connect the Text Agent to the Qdrant retrieval system.
2. Connect the Vision Agent to extracted PDF images and a Vision-Language Model.
3. Connect the SQL Agent to the database/Text-to-SQL system.
4. Replace keyword-based Supervisor routing with LLM-based query classification.
5. Implement final answer synthesis from the selected agent.
6. Evaluate whether the Supervisor correctly chooses vector search or SQL for different queries.

The project plan specifically identifies the mid-project goal of proving that the Supervisor can correctly choose between vector-database search and SQL based on the user's prompt.
